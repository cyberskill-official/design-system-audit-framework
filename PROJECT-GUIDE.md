# DSAF Project Guide (for agents and new contributors)

Root `AGENTS.md` is the CyberOS Layer-1 Memory Protocol (governs `.cyberos-memory/` only). THIS file is the project-level guide: what DSAF is, how to build it, and which gates protect it.

## What this repo is

DSAF audits design systems against a 125-criterion, 20-category maturity rubric (docs/framework/03-full-criteria.md), reporting DSAF Levels L0-L5 and an enterprise-grade floor verdict. Two audit paths exist and complement each other:

1. Deterministic engine — `scripts/bin/maximal-audit.mjs`. Three-band evidence scoring: prose mentions (max 40) + structural artifact probes (max 40) + verification signals (max 20). Prose alone can never claim "Built". Emits `ANALYZED_DESIGN_REPORT.md`, `scores.json` (schema `dsaf-scores/1`), `output-artifacts/evidence-index.json`.
2. LLM-driven SCAN/FIX — docs/guidelines/prompts/. A human-gated deep audit; the engine's output is its evidence floor, never its ceiling.

## Commands

```bash
npm run verify                 # full contract + calibration suite (the gate; keep GREEN)
npm run audit:maximal -- --input <repo|DESIGN.md|url> --out <dir> [--profile dsaf-25]
npm run audit:diff -- --baseline <old scores.json> --current <new scores.json>
npm run evolve:mine            # human-gated evolution proposals from calibration scores
npm run audit:maximal:cases    # exploratory 30-case loop (network + git clones)
npm test                       # workspace tests
```

## Layout

- `docs/framework/` — the rubric, tiers, regression policy, DSAF-25 core, templates.
- `docs/guidelines/` — how to run audits; prompt pack.
- `docs/internal/` — strategy, branding, launch (never gates the open methodology).
- `scripts/bin/` — engine + loop + diff + miner; `scripts/checks/` — contracts; `scripts/lib` + `scripts/test` — contract libs and node:test suites.
- `packages/` — cli, github-action, storybook-addon, tokens-validator, zeroheight-reader, figma-plugin.
- `docs/outputs/` — GITIGNORED, regenerated by checks; never hand-edit.

## Non-negotiable invariants

- `npm run verify` green before any commit lands.
- No silent regressions (docs/framework/05-regression-policy.md): score drops need a signed override row; `audit:diff` enforces this mechanically.
- The engine never fabricates target evidence (no mock artifacts) and prose-only inputs cap at 40/100 (`check-engine-robustness` pins both).
- Rubric changes (criteria rows, keywords, probes) are human-gated: the miner writes proposals under `docs/outputs/generated/evolution/`; a person lands them via PR and bumps `dsaf_125_version` in docs/framework/dsaf-25.md.
- README shape is contract-pinned (`contract:readme`): keep the first-200-words pitch, visual positions, and no funnel copy.
- Report shape is contract-pinned (`check:maximal:cases`): section headings and the wide criterion table header must not change without updating the contract in the same commit.

## The auto-evolution loop

Weekly CI (`.github/workflows/self-evolution.yml`) re-verifies the calibration corpus and uploads mined proposals. The primary living target is the CyberSkill Design System (sibling repo `../design-system`), which audits itself against this framework via `npm run audit` on its side and gates regressions against a committed baseline. Findings flow back here as vocabulary/probe/rubric proposals. The loop proposes; a human disposes.
